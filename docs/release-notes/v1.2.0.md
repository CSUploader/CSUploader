## Highlights

**Eighteen new file hosters** — CSUploader now uploads to **46**, up from 28. Nine of them need no
account at all: 1Fichier, DailyUploads, DropMeFiles, FILEAXA, Sendspace, UsersDrive, VikingFile,
Webshare and Send.now, bringing the no-login total to twenty.

Also in this release: the wizard shows each hoster's **parallel-upload limit**, and a run of
reliability work aimed squarely at the ways an upload can fail *quietly* — a dead CDN node, a
momentary Cloudflare error, or a server that answers "OK" and stores nothing.

## New file hosters

**No account needed** — pick "Anonymous" in the wizard:

- **1Fichier** — 5 GB per file for guests.
- **VikingFile** — anonymity is first-class in its own API; no cap encountered.
- **Sendspace** — 300 MiB. The reply to the upload *is* the result page, delete link included.
- **Webshare** — 1 GiB per chunk, chunked above that.
- **DropMeFiles** — 50 GB, the largest guest allowance here. ⚠ Links **expire** (14 days at most), so
  treat it as a transfer service rather than storage.
- **UsersDrive** — 5250 MB.
- **DailyUploads** and **FILEAXA** — 100 MiB chunks, no stated per-file ceiling.
- **Send.now** — 100 GB for guests, unlimited with an account.

**With an account:**

- **DDownload**, **Clicknupload**, **Uploady**, **Uploadrar**, **Filedot**, **TeraBytez** — the
  XFileSharing family, each signing in through the built-in browser.
- **Turbobit** — HitFile's sibling platform.
- **Filestank** — the first YetiShare host. ⚠ Free accounts get roughly **10 uploads a day**; the app
  now stops a batch cleanly when that allowance runs out instead of failing file after file.
- **DataVaults** — paste an API key from its My Account page.

## Uploads and reliability

- **"Max parallel" column** in the wizard's hoster step, showing each host's own concurrency limit.
  Most say "No limit"; the ones that don't are now honoured by the scheduler — DropMeFiles 5,
  Send.now 4, DataVaults 4, GigaPeta 1, ufile.io by account tier.
- **Dead upload nodes are remembered.** Some hosts hand out a rotating node and one of them is simply
  broken — measured on DailyUploads, where a particular node refused every upload while its siblings
  took the same file. The client now steps over a node that has failed, for ten minutes, so the file
  that discovers it spares the rest of the batch.
- **A server that accepts a file and stores nothing is now reported as a failure.** One host answered
  a discarded upload with a success shape (`file_status: OK`, `file_code: undef`), which would have
  produced a working-looking link to nothing.
- **A momentary CDN error no longer costs the upload — or the sign-in.** Cloudflare 5xx answers during
  the upload-server lookup are retried, and (the worse case) an error page is no longer mistaken for
  "your session expired", which used to discard a perfectly good sign-in and re-prompt.
- **Blocked file types are refused before the upload, not after.** Uploadrar rejects common video
  formats and filedot.to rejects images — both only at the final step, after the whole file has
  transferred. CSUploader now checks locally and says so immediately.
- **Sendspace** retries against a fresh node when one is down, and **1Fichier** retries when a node
  can't open its destination.
- **Correct file-size caps up front.** Files too large for a host are rejected when queued rather than
  after a doomed transfer — including per-tier caps where a host publishes them.

## Sign-in

- Sign-in is **serialised per account**, so starting ten uploads to a new host opens one browser
  window rather than ten.
- A sign-in window that used to stay open after a successful login now closes on hosts whose login
  page is a query route.
- **Accounts added from the upload wizard** now appear in Settings → Accounts, as they always should
  have.
- Account names are read correctly on hosts whose themes don't publish one the usual way — previously
  some accounts saved blank, or picked up the word "Profile" from a menu.

## Fixes

- The Logs and Uploaded tabs no longer log a binding error on every tooltip hover.
- Settings' Connection panel no longer logs a binding error at startup.
- Log entries render each HTTP header as the single line that actually goes on the wire.
- Wizard grid headers use the app's own header styling; italic hoster names are no longer clipped.
- A package's **Elapsed** time is a wall-clock span again, not the sum of its files' times — a package
  re-added under an existing name no longer inherits a nonsense duration.
- Multipart uploads write `Content-Disposition` before `Content-Type` on file parts, matching browsers
  and curl. One host silently accepted whole uploads and then reported "no file found" without it.

## Notes

- **DropGalaxy** and **ShareMods** are present in the code but disabled: DropGalaxy caps anonymous
  uploads at roughly ten bytes and has closed signups, and ShareMods began serving this client a
  Cloudflare challenge before its first release. Neither is offered in the wizard.
