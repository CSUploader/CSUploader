## Highlights

**CSUploader now looks for updates before it opens — and from the next release on, tells you what
they contain.** A small splash checks at startup, and anything it finds is offered before the main
window appears, before any queued upload can auto-start. Two new settings decide how much of that
you want. The History tab learned to search, and every language the app speaks now says every
string.

## The startup update check

Launching an installed CSUploader shows a brief "Checking for updates…" splash. If an update is
found, you are asked — **Update now** or **Later** — before the main window opens, which means
before any queued upload can auto-start: choosing to update never restarts the app mid-transfer.

Two settings under **Settings → General** control it, because checking and installing are two
different questions:

- **Check for updates at startup** (default on) decides whether the check runs in front of the
  window or quietly behind it. Turning it off is not turning updates off — the app opens straight
  away and the check happens just after, so the title bar still tells you when something is new.
  The six-hourly background check is unaffected either way.
- **Install updates automatically at startup** (default off, available only while the first is on)
  installs whatever the startup check finds without asking. Off keeps the existing behaviour: the
  update is offered, you decide. It defaults to off deliberately — installing restarts the app, and
  that should never happen to someone who did not opt in.

Builds that are not installed — running from source or from unpacked build output — check too now,
instead of skipping silently. They report a newer version through **Help → Check for Updates** but
never offer to install it, because there is nothing an uninstalled build could update.

Two smaller things in the same area: **Help → Check for Updates** now gives up waiting after 20
seconds instead of hanging for as long as a slow check takes, and the **About box no longer shows a
stale version** — it used to read a number the release process never updated, so it would have gone
on introducing this release as 1.5.0.

## The update prompt will show what's new

From this release on, every update package carries its own release notes, and the prompt renders
them in a scrollable "What's new" section — so "Update now or later?" comes with the reason to
care. You will see it for the first time when the release *after* this one is offered: updates
published before v1.6.0 carry no notes, so this prompt appears without the section exactly once.

## The History tab has a search bar

History grows forever, and until now the only way to find an old link was scrolling. The bar at the
bottom of the tab filters as you type — by file name, package name, hoster or URL,
case-insensitively. Searching a package name keeps the whole package visible, groups expand so a
match is never hidden under a package you collapsed earlier, and an active search stays applied
when the list refreshes.

## Every language says every string

51 strings still showed English in Japanese, Korean, Simplified Chinese, Vietnamese and Filipino:
the copy-links menu, the account sign-in flow, the browser sign-in window, the Logs columns, the
upload overview labels and the upload wizard's summary page. All of them are translated now, in
each language's established terminology — and the build gains a stricter gate, so a future string
cannot ship untranslated or with a broken placeholder without failing a test first.
