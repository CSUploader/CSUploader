## Highlights

**One tick now narrows the hoster list to destinations that put no puzzle in a downloader's way.**
1.4.2 added the **"Download captcha?"** column — the verdict, per host, on whether whoever you share
a link with has to solve a captcha to get the file. This release makes that verdict *actionable*: a
**"No download captcha"** checkbox joins the File Hosters step's filter bar, and ticking it leaves
only the **32 hosters whose ordinary free-download flow was verified captcha-free**.

## The "No download captcha" filter

- **It sits beside "Anonymous only"** on the filter bar, and the two read the same way: tick to
  narrow, untick to widen.
- **The three filters AND together.** The name box, "Anonymous only" and "No download captcha" each
  cut independently — tick both boxes and type `file`, and you get captcha-free, account-free
  hosters whose name contains "file". Neither toggle stands in for the other: FileGarden, for
  instance, is captcha-free *and* account-only, so it survives one and not the other.
- **"Clear filter" resets all three**, not just the text box.
- **Unverified hosters are hidden, not kept.** The five hosts carrying the column's em dash — and
  any host with no verdict at all — drop out of the list when the box is ticked. This is the point
  worth stating plainly: the filter's promise is that a downloader meets no captcha, and *Unknown
  has never meant that*. Keeping the dashes would have quietly broken the promise for whoever
  trusted the tick. It is the same honesty rule the column itself was built on.
- **Filtering stays a view concern.** A hoster you tick and then filter out of sight is still
  selected and still uploads — the "showing N of M" hint beside the bar is what tells you the list
  is narrower than the selection. Likewise, check-all only ticks the rows the filter is currently
  showing.

## Why this is a filter and not a sort

The captcha column has been sortable since 1.4.2, and sorting groups the Yes/No/unknown blocks
together — but it still leaves 76 rows to scroll and puts the unknowns adjacent to the Nos, which is
exactly the adjacency that invites a mis-click. A filter removes the question instead of arranging
it. Pick the box when what you care about is "my downloaders must not hit a captcha"; use the sort
when you want to see the whole landscape.

The full research register behind each verdict — the Yes/No call, its confidence, the date it was
checked and the evidence for it, per host — lives in
[docs/hoster-download-captcha.md](https://github.com/CSUploader/CSUploader/blob/v1.4.3/docs/hoster-download-captcha.md).

## Notes

- The checkbox and its tooltip are localized in all six languages, like the rest of the wizard.
- Verdicts describe each host's *ordinary* flow, so the filter inherits that scope: a captcha-free
  host that arms a challenge only against flagged or rate-limited traffic still passes.
- Wait timers don't count as captchas here, so a host can pass this filter and still make free
  downloaders sit through a countdown — the column's header tooltip has said so since 1.4.2.
- No verdicts changed in this release; the 32/39/5 split is the one 1.4.2 shipped.
