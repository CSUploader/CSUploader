## Highlights

**The upload wizard learns how you work.** Two settings that stop you re-making the same choice every
time you open it: which hosters the list shows, and which folder the file pickers open in. Plus two
fixes for problems Linux users were hitting and Windows users never saw.

## Filter the hoster list by upload mode

The File Hosters step's **"Anonymous only"** checkbox becomes an **Accounts** dropdown with three
positions:

- **Both** — every hoster, the default.
- **Anonymous only** — hosters that take uploads with no account at all.
- **Account only** — hosters that *offer* accounts.

That last one is worth reading carefully, because the obvious definition would have been wrong.
"Account only" is **not** "everything that refuses anonymous uploads" — the two capabilities overlap.
catbox, gofile, ufile, upload.ee and UpZur all take anonymous uploads *and* offer accounts, so they
appear under **either** narrowing. Treating account as the inverse of anonymous would have hidden
exactly the hosters that give you a choice of route. Neither mode asks whether you *have* an account;
the row already says that with a padlock.

It ANDs with the name box and **"No download captcha"** exactly as before, the "N of M shown" hint
still tells you the list is narrower than your selection, and **Clear filter** still returns
everything to Both.

**Settings → Upload → Upload Wizard** now carries the mode the wizard *opens* on, for anyone who only
ever uploads one way. Clearing the filter inside the wizard still goes to Both regardless — Clear
means clear.

## Default upload directory

**Settings → Upload → Upload Wizard → Default upload directory.** "Add files…" and "Add folder…" open
there.

Leave it empty — the default — and they reopen **wherever you last browsed**, remembered across
restarts. What gets remembered is the picked item's *parent* folder, for a folder as well as a file,
so reopening shows what you just picked next to its siblings: the next season, the next release, one
click away. A configured directory always wins, and the last-used folder keeps being recorded behind
it, so clearing the box lands somewhere useful immediately rather than on a cold start.

Underneath this, the file picker gained a start directory it never had at all — it used to open at
whatever the OS considered home, however recently you had browsed somewhere else.

## Fixed

- **The "Download captcha?" column header broke mid-word** on Linux, rendering as "Downloa /
  d captcha?". The column's 80px left the header 60px of text budget against a 57px string — three
  pixels of margin, which held in Segoe UI and did not in the wider default UI fonts on Linux. The
  column is 100px now, clearing the same string by 40%. The wizard window went 850 → 940 at the same
  time so the Account column doesn't pay for the extra width. Worth knowing if you ever relabel one
  of those slim columns: the budget is the column width minus 12px of header padding minus an 8px
  sort-glyph reserve, and it has to clear the longest **word**, not the whole string.
- **The wizard no longer advertises drag-and-drop on Linux.** It was never going to work there:
  Avalonia's X11 backend implements no XDND — it defines none of the `Xdnd*` atoms the protocol
  requires, so its windows never advertise themselves as drop targets and no file manager will even
  offer them a drop. Windows (a full OLE drop target) and macOS are unaffected. Showing the hint
  anyway made the app look broken rather than the feature look absent, which is exactly how it was
  reported. Use **Add files…** / **Add folder…** on Linux.

## Notes

- All new strings are localized in the usual six languages.
- The drop *handler* is still wired on every platform. It costs nothing where the event never fires,
  and drag-and-drop will start working on Linux by itself if Avalonia implements XDND.
- No hoster verdicts, size caps or retention figures changed in this release.
