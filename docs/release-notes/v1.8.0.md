## Highlights

**Updates now download only what changed, and every column on the Uploads tab sorts.** A release
that only touches app code arrives as a fraction of a megabyte instead of the whole 63 MB package —
and the upload queue can finally be ordered by hoster, name, size, status, progress or order,
without packages and their files coming apart. Two hosters that were failing uploads they should
have completed, DropMeFiles and Litterbox, are fixed.

## Updates download only what changed

Until now every update downloaded the entire application again: 63 MB on Windows, 196 MB on Linux,
whether the release rewrote half the app or fixed one line. From this release on, each release
ships a *delta* package alongside the full one — just the bytes that differ from the previous
version — and installed builds apply the delta when they can.

The update *to* this release already downloads small. Nothing changed in the app to make this
work; installed CSUploader has always known how to apply a delta, the packages simply never
existed for it to find.

Builds more than ten versions behind, or without a usable chain of packages to patch through,
quietly fall back to the full download exactly as before. You do not have to choose, and there is
no setting: the app takes the smaller path when one exists.

## Every column on the Uploads tab sorts

Clicking **Hoster**, **Name**, **Size**, **Status**, **Progress** or **Order** used to do nothing
at all. All six sort now, like the columns that already did.

Sorting is hierarchical, which is the part worth knowing about. Packages are ranked against each
other, and each package's files are ranked *within* it — so a package always stays directly above
its own files instead of the grid collapsing into one flat list where files land next to strangers.

Two things it deliberately does not do:

- **It does not change upload order.** Sorting only changes how the queue is displayed. What
  uploads next is still the queue's own order, the one driven by the **Order** column and
  **Move Up** / **Move Down**. Moving a row clears the sort, so the grid returns to that order and
  you can see what you are actually rearranging.
- **It does not make rows jump while uploads run.** Rows are ranked as they stood at the moment you
  sorted, and then hold still. Sorting by Speed or Progress on a live queue would otherwise be
  unreadable — rows reshuffling under the pointer every time a number ticked. Click the header
  again to re-rank against current values.

Your sort is remembered between restarts, alongside the column widths and visibility that already
were.

## Two hosters stop failing uploads

**DropMeFiles no longer refuses batches with "Spam".** The host's anti-abuse answers a burst of
uploads from one address by rejecting them outright, and the app was letting five run at once —
enough to trigger it, so files failed before they had started. Uploads to DropMeFiles now go one at
a time. This is slower for a large batch by design; a batch that finishes slowly beats one that is
refused.

**Litterbox retries when its server has a moment.** An upload to Litterbox was given up on after a
single try, so a passing server-side hiccup — an internal server error, or the host answering
"No file!" after it had already received the whole upload — failed the file outright. Those two now
get up to three attempts. Refusals that are genuinely about the file, such as it being too large,
still fail immediately: re-sending it would only earn the same answer at the cost of uploading it
again.

## Help → Check for Updates shows the splash while it checks

The menu item used to wait invisibly — up to twenty seconds with nothing on screen, which read as
the app doing nothing at all. It now opens the same "Checking for updates…" window CSUploader shows
at launch, centered on the main window, and the answer replaces it.

Closing the splash means "stop waiting": no result dialog appears, and the check carries on in the
background with its normal background reporting.

## The mock-server switch is a developer-build feature now

Settings gains a **Developer** category holding the "use mock server" option that used to sit under
**General**, and that whole category exists only in development builds — a released CSUploader no
longer carries it. The setting is ignored outside a development build in any case, so a flag left
switched on cannot follow a build into a release and quietly send every upload to localhost.
