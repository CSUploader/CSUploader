## Highlights

**CSUploader now runs on Avalonia 12.1, the current release of its UI framework.** The app is
meant to look and behave exactly as it did — this release moves the foundation, not the furniture.
It also fixes a bandwidth leak in parallel part uploads: once a hoster rejected a part, parts
still waiting for their turn could keep starting anyway.

If you are reading this inside the update prompt: that is v1.6.0's "What's new" section showing
its first real notes.

## The framework under the app

Avalonia is the toolkit CSUploader's whole interface is built on, and this release moves it from
the 11 line to the current 12.1 line. The move is intended not to change how the app looks or
works. All automated suites ran on Windows; the app itself was live-checked on both Windows and
Linux, including browser-based account sign-in on Linux.

A concrete reason to make the move now: Avalonia 12.1 adds drag-and-drop (XDND) support to its
Linux backend. CSUploader has so far withheld its drop-files-here hint on Linux because earlier
framework versions could not receive a drop there — this release lays the groundwork for a future
release to offer it on Linux too.

## A failed part upload stops its attempt sooner

Some hosters upload a file as several parts at once. When one part was rejected, the parts still
waiting for an upload slot could keep starting — spending your bandwidth on an attempt that could
no longer succeed. Once a part has failed, the waiting parts no longer start. This does not change
whether the upload is retried; the existing attempt-level retry rules still make that decision.
